# Contracts

These JSON files are **generated by the backend**, not written here.

```bash
# in the backend repo
make contracts        # writes contracts/*.json
make contracts-check  # fails if they are stale
```

Copy them into this directory (CI does it by downloading the backend's build
artifact) and `src/__tests__/contracts.test.ts` asserts this repo's TypeScript
constants against them.

## Why this exists

The frontend hand-mirrors three things the backend owns: the response envelope,
the list query-param names, and the permission codes plus their subsumption
rules. Nothing in either language checks that the mirror is accurate, and both
sides compile perfectly while disagreeing.

That is not hypothetical — it is why this was built:

- The backend renamed `limit` to `page_size`. The frontend kept sending `limit`,
  the backend ignored it and used its default, and every list silently paged at
  the wrong size until someone noticed the row counts.
- `build_parameters_config()` emits `label` and `type`; the frontend's
  `FilterConfig` declared `display_name` and `allow_multiple`. Filter headings
  rendered blank.

Both were caught by reading code, months apart. The test turns the next one into
a red build.

## Updating a contract

Change the backend, run `make contracts`, copy the files here, and fix whatever
the test now reports. The test failing is the system working — do not edit the
JSON by hand to make it pass.
